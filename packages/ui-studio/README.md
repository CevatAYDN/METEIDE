# @mete/ui-studio

Studio view (PixiJS). Visual reference: docs/19-studio-view-prototype.md.

Modules: ui-studio

Today the package holds the run view model the Team panel's views share (ADR-051, docs/13): `applyEvent` and `applyAll` fold one run's events into a `TeamView`, each event id applied once, so the history from `mete/events` and the live `mete/event` stream can overlap. Cards are placed by task status alone (`placeOf`: the Board columns of ADR-051). It depends only on `@mete/contracts` and is a library, not a kernel module yet. Agents are folded too (`agents.ts`): each with its role, provider and model, its task, whether it is thinking and the tool it waits on, from the envelope agent id the core sets (shortcut: messages join with the Studio's animations; the request count of a character card waits for an event that names the agent, since the quota module publishes `quota.*` without one; the animations come with tween.js). The fold also keeps the Studio's signals (`signals.ts`: the roles seen approving or reviewing, why the run is paused, and the workspace's spent quotas), and `sceneOf` turns a view into the studio room of docs/13 and ADR-052: desk rows of at most six, lead roles first, one character per role above twelve agents, each idle, thinking, working on a tool or waiting for quota, and the board's notes by column. `paintScene` (`paint.ts`) turns a scene into rects, circles and text in the `@mete/ui-kit` token colours of the theme mode, and `createStage` (`stage.ts`) draws them on a PixiJS canvas, loading `pixi.js` only then, with no ticker.
