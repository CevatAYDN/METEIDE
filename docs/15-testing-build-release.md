# 15 Testing, build and release

Repository file: `docs/15-testing-build-release.md`. Depends on: 05 Tech stack, 14 Coding standards.

All checks run on the developer's machine through lefthook and package scripts; tests never call real models; releases are built locally for Windows and, through WSL2, for Linux \[C\].

## Test types

| Type | Tool | Scope | When |
| --- | --- | --- | --- |
| Unit | Vitest | Domain and application code | pre-push, affected packages |
| Integration | Vitest, real SQLite in a temp folder, in-process kernel | Package boundaries | pre-push, affected packages |
| Contract | Kits in `@mete/testing` | Every adapter of every capability | pre-push for touched capabilities; full at release |
| LLM replay | Hand-written fetch fakes and scripted adapters now; MSW cassettes once `pnpm test:record` exists | Agent flows with recorded or scripted model responses | pre-push |
| End-to-end | Playwright for Electron | Desktop flows: onboarding, run, approval, blocked task, quota pause, replay | release |
| Chaos | Seeded script | Disable optional modules one by one and in random sets; the app must start and finish the single-agent fixture task. `pnpm test:chaos` leaves each optional module of the CLI's composition out, then five sets drawn from `CHAOS_SEED`, then all of them, and finishes the typo-fix fixture with a scripted provider each time \[D\] | release |
| MCP conformance | MCP Inspector, scripted | METE as server; METE as client against a Node, a Python and an HTTP reference server \[D\] | release |
| Accessibility | axe-core inside E2E | No serious or critical violations \[D\] | release |
| Security | Electronegativity, osv-scanner, `pnpm audit` (high and critical fail), `pnpm licenses list` | Whole repository | release |

Rules:

- Tests MUST NOT call real model providers. Cassettes are recorded only by `pnpm test:record` with the developer's own keys and committed with secrets masked \[C\]. `pnpm test:record` is not built yet; until it is, provider and gateway tests answer through hand-written fetch fakes and agent flows through scripted `provider.chat@2` adapters, and MSW stays the planned replay tool (tab 05).
- The desktop's end-to-end tests answer the real daemon with the same kind of script: `METE_SCRIPTED_CHAT` names a JSON file of chat turns (one array of chunks per model call, the last repeating), and the CLI's composition then uses the `provider-scripted` module instead of every provider (ADR-111). A test's app therefore needs no provider key, leaves the developer's keychain untouched and reaches no network, while the daemon, the gateway, the engine, the tools and the panels stay the real ones; `apps/desktop/e2e/run-flow.e2e.ts` drives a task that waits for approval, one that a guardrail blocks and the human's instruction lifts, and one whose provider's day is spent until the reset. `apps/desktop/e2e/templates.e2e.ts` starts the built-in research team from the run composer and checks the `research-report@1` its run writes, with the web answered by the script above. A script may narrow the scripted provider's unit with `{ turns, quota: { limit, reset } }`, which is how the quota flow pauses the real pool instead of waiting out a sliding minute (ADR-113); each test's app also keeps its global data — counted quota, logs, settings —, Theia's user folder (`THEIA_CONFIG_DIR`: recent and trusted folders) and Electron's own folder (`--user-data-dir`: the saved window size and the single-instance lock, which Electron finds through Windows' known folder and not `APPDATA`) in a temp folder, so the developer's own never enters a test and a test never enters theirs. The same app answers web calls from `METE_SCRIPTED_WEB`: a JSON file of `{ results, pages }` whose results every `web.search@1` call returns and whose pages `web.fetch@1` reads, while the app's keys stay in memory (ADR-116); the built-in Exa server stays offline and the chain falls back to Tavily, so a template that reads the web runs with no network and no key of the developer's. Browser calls come from `METE_SCRIPTED_BROWSER`, a JSON file of screenshot sizes and Lighthouse reports whose n-th entry answers the n-th `browser.screenshot@2` or `seo.audit@2` call, the last repeating; its runner writes the PNG and the report, Chromium counts as installed so nothing downloads, and the tools keep writing their files into `.mete/assets/` (ADR-117). The same suite can run against the packaged app: `METE_E2E_APP=packaged` starts the installer's `dist/installer/win-unpacked/METE IDE.exe` with the plugins that folder carries, in the same temp workspace and global folder, so the daemon, its database, the native modules and the tools' ripgrep are the ones a user gets; a folder that is not built stops the test with the command that builds it (ADR-124).
- Coverage targets: 90% of lines in `domain/` folders, 75% per package overall; `ui-theia`'s Theia bindings (widgets, contributions, modules, its RPC service and the commands that need Theia's services) run only inside Theia, so they are outside the unit measure and the desktop end-to-end tests cover them \[D\].

## Performance budgets

Phase 1 measures a baseline on the reference machine (the founder's Windows PC): cold start, idle memory, studio frame rate with 6 agents, and indexing time per 1,000 files. From then on, a release fails if any metric regresses by more than 10% from the last accepted baseline \[D\]. Absolute targets are set from that baseline, not guessed.

Phase 1 baseline, recorded from a live `mete run` of an edit task on the reference machine (cold start is the time until the workspace is open; the run figures come from `model_calls` and `runs`) \[D\]:

| Metric | Value | Measured | Commit |
| --- | --- | --- | --- |
| CLI cold start | 1.13 s, median of 5 `mete status` runs after a warm-up, Node 23.9.0 | 2026-10-22 | ab9f1c1 |
| Idle memory (RSS) | 130 MB at the end of `mete status`, median of 5 (101 to 158 MB) | 2026-10-22 | ab9f1c1 |
| Model calls per run | 21: 7 answered and 14 refused with 401 by two OpenRouter models on every turn | 2026-10-22 | ab9f1c1 |
| Prompt and completion tokens per run | 14,000 prompt and 412 completion over the 7 answered calls | 2026-10-22 | ab9f1c1 |
| Median model call latency | 1,065 ms for an answered call; 39 ms for a refused one | 2026-10-22 | ab9f1c1 |
| Run wall time | 9.4 s; 65.0 s when the refused calls used up OpenRouter's 20 requests a minute and the gateway waited 50 s | 2026-10-22 | fc12407, ab9f1c1 |

CLI cold start remeasured on 2026-10-23: 1.48 s, median of 5 `mete status` runs after a warm-up in an empty folder, on Node 24.21.0, the `devEngines` runtime `pnpm` runs (6c5b85b). It was 1.71 s before playwright-core loaded only on first need, and the same runs on Node 23.9.0 took 1.91 s, so the growth over the baseline comes from the CLI, not from Node; most of the rest is loading the ES module graph at start. Remeasured on 2026-10-25 in the same way: 1.75 s before the page parsers moved behind the first `web.fetch@1` call, 1.47 s after that, 1.35 s after the secretlint rules moved behind the first mask and 1.24 s (1.23 to 1.25 across two runs) after the MCP SDK's client and server moved behind their first use; that is 10% over the accepted 1.13 s, at the edge of the 10% rule, so the finding stays open until the release check measures it again.

Desktop baseline, recorded on 2026-10-25 with `pnpm --filter @mete/desktop test:perf` (commit bf2cbe0's script, three launches with this repository as the workspace, Theia 1.76 with the ADR-103 to ADR-105 built-ins) \[D\]: the shell is visible at 3.0 s (median) and the frontend contributions settle at 7.6 s (median), and the app's whole process tree holds 1.45 GB at idle over 9 processes — renderer 405 MB, the daemon the Home view starts 248 MB, the backend 216 MB, the extension host 174 MB, gpu 166 MB, the IPC helper 126 MB and the network utility 98 MB. The 10% rule above applies to these numbers, and the script prints them the same way every time, so a regression is a number, not a feeling. One outlier was seen once and never reproduced (a 65 s settle on the first launch after ADR-105's bundle); the perf script exists to catch such a start again.

The Phase 1 exit gate counts as passed on 2026-10-22 \[D\]. Live runs finished the edit task with free providers only (fc12407, ab9f1c1) and recorded the baseline above. Quota exhaustion paused live runs: OpenRouter's daily limit ran out on 2026-10-21, and twice `quota.exhausted` was followed by `run.paused` with reason `quota` and `resumesAt` at the reset. Both runs were cancelled before the reset, so the automatic resume is covered only by tests (`packages/core/test/application/engine.test.ts`, "pauses on exhausted quota and resumes by itself at the reset"). The first live run that goes through a reset closes this gap.

## Local CI

| Hook or script | Runs |
| --- | --- |
| pre-commit | Biome on staged files, `tsc --noEmit` on affected packages, dependency-cruiser |
| pre-push | Unit, integration, contract and replay tests on affected packages; secretlint on the diff |
| `pnpm release:check` | Every test type above, all security checks, all builds the machine can produce |

## Builds

| Target | Format | Built on |
| --- | --- | --- |
| Windows x64 | NSIS installer \[D\], built by `pnpm --filter @mete/desktop package:win` after `bundle` and `download:plugins` (ADR-115) | Windows |
| Linux x64 | AppImage and `.deb` \[D\] | WSL2 |
| macOS | After MVP \[C\] | A Mac, later |
| CLI | npm package `@mete/cli` with binary `mete` \[D\]; also bundled in the desktop app | Any |

- Installs use `pnpm install --frozen-lockfile`.
- Native modules MUST have prebuilt binaries. Desktop builds rebuild them for Electron's ABI with `@electron/rebuild`; the CLI uses Node.js ABI prebuilds \[C\].
- The installer is packed over a `pnpm deploy` staging folder, not over the repository (ADR-115): the app ships a real, flattened `node_modules` tree, `asar` stays off because Theia loads native modules and spawns executables from the app folder, and `templates/` and `adapters/` land in `resources/`, which the daemon the app starts reads through `METE_TEMPLATES_DIR` and `METE_ADAPTERS_DIR`. When `lib/`, `plugins/` or electron-builder is missing, the script names the command to run first. `bundle` builds the frontend in production mode, and electron-builder's `files` patterns keep the workspace packages' sources, tests and coverage out of the installer; the packages' own `files` fields still shape what `pnpm pack` ships.

## Release process

1. `pnpm changeset version` updates versions and changelogs.
2. `pnpm release:check` passes. It runs every release-tier check and reports them once: `pnpm check`, all tests (the contract kits included), `pnpm test:chaos`, `pnpm check:mcp`, `pnpm audit --audit-level high` (except the two advisories of `decompress`, which has no fixed release and unpacks only the pinned built-ins at build time, ADR-103: `auditConfig.ignoreGhsas` in `pnpm-workspace.yaml` names them), `pnpm licenses list --prod` (the licenses of what ships; a license outside the docs/05 list fails it, an SPDX `OR` passing when one choice is allowed), osv-scanner (it must be on `PATH`), Electronegativity on the desktop's main process (a HIGH finding fails it, like a high audit finding, except `LIMIT_NAVIGATION_GLOBAL_CHECK`: Theia blocks `will-navigate` and limits `window.open` with `setWindowOpenHandler` for every web contents, which the check, written for the removed `new-window` event, does not see), the desktop bundle and the end-to-end tests (Playwright driving the app's own Electron, the axe-core accessibility tests among them; apps/desktop/README.md says how they launch), and the Windows installer (ADR-115), which it builds and which fails the step when the build fails or leaves no `.exe` behind \[D\], and then the packaged app's own end-to-end tests, `test:e2e:packaged`, which run the onboarding and a run that reads and searches the workspace against that folder (ADR-124).
3. Build Linux in WSL2.
4. Generate SHA-256 checksums for every artifact.
5. Publish through `release.publish@1`; the default adapter runs `gh release create` from the developer's machine \[C\].
6. electron-updater reads the same release for Windows and Linux AppImage updates \[C\]. The user asks for it with Help → "Check for Updates…": a newer release downloads, then "Restart now" installs it; with no release published, or in an app run from source, the answer says so (ADR-137) \[D\].

Signing: builds ship unsigned first; the README explains the SmartScreen warning step by step. An application to SignPath Foundation for free Windows signing is part of Phase 7 \[C\].

Versions: SemVer. The public MVP is `0.1.0`. `1.0.0` comes after macOS support and a frozen plugin API \[D\]. A breaking kernel API change needs a major version and a migration guide.
