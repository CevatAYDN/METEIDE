> ### 1. SSRF/DNS-rebinding açığı `web.fetch@1` — dosya kendi itiraf ediyor
> Kanıt `packages/tools/src/domain/addresses.ts:1-54`:
> ```ts
> // web.fetch@1 reaches the public web only ... Pure.
> // shortcut: literal hosts only; a public name that resolves to a private address (DNS
> // rebinding) is not caught; check resolved addresses when an allow list ...
> ...
> export const isPublicHost = (hostname: string) => {
>   ...
>   if (isIPv4(host)) return !privateV4(host);
>   if (isIPv6(host)) return !privateV6(host);
>   return true; // <- DNS'e hiç bakılmıyor
> };
> ```
> `privateV4/V6`, `LOCAL_NAMES` kontrolleri doğru yönde ama yalnızca literale bakıyor. Çözüm olması gereken: `fetch` öncesi `dns.lookup(host)` ile tüm A/AAAA kayıtlarını al, her birini `privateV4/V6` + `LOCAL_NAMES` ile ele, geçici DNS TTL hilesine karşı bağlantı kurulan IP'yi sabitle (pin) veya en azından `lookup` sonrası `fetch`'i özel ajanda o IP'ye kilitle; zaman-aşımı ve IPv6 mapped (`::ffff:127.0.0.1` hex biçimi dahil) testleri ekle. `SECURITY.md` tehdit modeline bu maddeyi işle.
